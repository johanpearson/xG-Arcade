## 5. Test Coverage Gaps by Testing Level (new this revision)

**Method:** every `REQ-xxx` header in `docs/requirements-document.md` (141 total, 3 explicitly `Status: Deprecated` and excluded) was cross-referenced against `REQ`-named test methods/comments in `backend/tests/**/*Tests.cs` (NUnit unit + `WebApplicationFactory` API tests are not separately taggable by convention in this repo, so both test levels were searched together and disambiguated by reading the matching file), `frontend/src/**/*.test.{ts,tsx}` (Vitest), and `frontend/tests/e2e/*.spec.ts` (Playwright). This is a coverage-*existence* check (does at least one test reference this REQ anywhere), not a coverage-*quality* audit — a REQ with one matching test may still be thinly covered; the two findings below were confirmed by reading the relevant file directly, not from the grep alone.

**Backend (NUnit unit + API):**
- **REQ-603 (data consistency under concurrent guesses)** — no test anywhere in `backend/tests/` exercises concurrent/parallel guess submission against the uniqueness calculation (`Task.WhenAll`/`Parallel.ForEach`-style concurrency tests exist for a few unrelated repositories — `PlayerRepositoryTests.cs`, `PredictInstanceRepositoryTests.cs` — but none target `UniquenessScoringStrategy` or its call path). This is the one NFR in `docs/requirements-document.md` §4.8 explicitly calling out race-condition correctness ("no race conditions producing an incorrect percentage") with no test evidence it's been verified either way. **Flag for `test-writer`**, not this report — writing the test is new coverage, outside this lineage's pure-refactor epic scope.
- **REQ-702/703/704/706 (unconfirmed-account blocking, confirmation email content, resend, deferred round-result email)** — `AuthEndpointTests.cs`'s own header comment (line 19) states it is deliberately "scoped to REQ-701's checkbox clause only (REQ-702 through REQ-705 — confirmation flow — and REQ-606 rate limiting excluded)"; no other test file in the repo picks up that explicitly-excluded range with `REQ702`/`REQ703`/`REQ704`/`REQ706`-named tests. (REQ-705 — confirmation link expiry — does have coverage elsewhere, confirmed via `AuthEndpointTests.cs` references; it's the other three in the same story-note that are open.) Since ADR-0005 puts confirmation-email *sending* in Supabase's hands, the in-repo surface to test is narrower than the REQ text alone suggests (mainly: are unconfirmed accounts actually blocked from play, REQ-702) — but that narrower surface still has no dedicated test. **Flag for `test-writer`.**
- REQ-901/REQ-902 (backups, failure alerting) and REQ-804/REQ-805 (prod/dev data sync) are correctly untested in the traditional sense — `MVP-SCOPE.md` marks REQ-901/902 "not needed yet" and REQ-804/805's own `docs/requirements-document.md` "Test level" line calls for Integration + Manual verification, not unit/API tests; not a gap, a scope note.
