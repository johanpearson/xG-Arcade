## 4. Priority Refactoring Targets

### 🟠 Hotspot-in-Progress (Medium-High Complexity, Rising Churn)

1. **`backend/src/XGArcade.DataSync/Wikidata/PlayerCareerPrefetchService.cs`** (408 lines, highest churn in `XGArcade.DataSync` this pass — 8 commits since 2026-08-11) — replaces the now-resolved `XGPathGameModule.cs` finding at this slot. The country-sweep and club-sweep `foreach` loops in `PrefetchAsync` are ~90 lines each and near-identical in shape (skip-on-null-QID, fetch-with-try/catch-log-continue, mark-swept via `UpdateCountrySweptAtAsync`/`UpdateClubSweptAtAsync`, skip-empty-pool, batch into `FetchAndPersistBatchAsync`, log running totals) — the club loop was added by S-127 as a deliberate mirror of the pre-existing country loop (ADR-0069), and every subsequent story since (REQ-110/ADR-0077/ADR-0078/S-159/S-160) has touched both loops symmetrically, growing the duplication rather than shrinking it. Not yet critical — well-tested (563-line `PlayerCareerPrefetchServiceTests.cs`), and each loop's own real behavioral nuance (the club loop's deliberate `club.Name`, not `clubNameByClubQid`, attribute-value sourcing) is already correctly documented inline — but the clearest next duplication-risk target by complexity × churn. **Fix:** extract a shared `SweepPoolAsync`-shaped helper both loops call, preserving every nuance verbatim — see `docs/backlog.md` Epic 21 S-165.

### 🟡 Large-but-Healthy (Watch, Not Urgent)

1. **`backend/src/XGArcade.Games.XGPath/PathCareerStintFilter.cs`** (544 lines, 7 commits) — grew from S-138 through S-163 as each new xG Path data-quality bug added its own independently-testable static filter method (national-team exclusion, B-team exclusion, adjacent-same-club collapse, inferred-loan labeling). Inspected this pass and found genuinely cohesive: one responsibility ("read-time filters/transforms over an already-fetched `PlayerCareerStint` list"), the actual code under 100 lines total — the rest is this codebase's established heavy-inline-rationale documentation style (same convention as `IWikidataClient.cs`), each method with its own dedicated test coverage. Not the same accretion failure mode `XGPathGameModule.cs` had. No action; re-check if the next 1-2 xG Path data-quality bugs add yet another method here.
2. **`backend/src/XGArcade.Api/CompositionRoot/CliVerbDispatcher.cs`** (769 lines) — unchanged since 2026-08-18 (confirmed via `git log --since`), still a healthy verb-registry pattern. No action.
3. **`backend/tests/XGArcade.DataSync.Tests/Wikidata/WikidataClientTests.cs`** (3,973 lines, still the single largest file in the repo including tests) — unchanged this pass. Growing for legitimate regression-proof reasons. Same judgment the 2026-08-11 revision already made; still holds.
